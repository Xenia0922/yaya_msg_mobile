## A. 本轮已定位、待动手

### A1. 直播弹幕输入条不顶输入法 ★ 新报

**现象**：直播播放器底坞的弹幕输入框（`LiveBarrageBoard` 的 `inputOnly` 底坞）弹出软键盘时不会上移，被输入法整个盖住，没法边看边打字。

**根因**：播放器页面（`MediaScreen` 的 `styles.playerPage`，`position:'absolute'` 全屏浮层）**没有任何键盘避让**。全仓 grep 确认：`src/player/PlayerScreen.tsx` / `src/screens/MediaScreen.tsx` / `src/player/chrome/PlayerChrome.tsx` 三处**零命中** `KeyboardAvoidingView` / `Keyboard` / `keyboardVerticalOffset`。而 `playerPage` 是 `position:absolute` 的浮层，Android 默认 `adjustResize` 对它无效（RN 根 View 缩放不含 absolute 浮层，且宿主的 `windowSoftInputMode` 需确认）。

**修法**：在播放器浮层里订阅 `Keyboard` 事件拿键盘高度，把底坞（`PlayerChrome` 的底栏容器）`translateY(-keyboardHeight)`；或给 `playerPage` 套 `KeyboardAvoidingView behavior="padding"` 并确认 Android `windowSoftInputMode=adjustResize`。

**涉及文件**：`src/screens/MediaScreen.tsx`（playerPage 容器）、`src/player/chrome/PlayerChrome.tsx`（底坞）、`src/components/LiveBarrageBoard.tsx`（输入条本体）

**两个版本都要**（通用修复）

### A2. 从首页/房间进直播不显示公告 ★ 新报

**现象**：从首页直播卡（或房间页）点进播放器，公告面板永远不出现，即使这个直播确实有公告。只有在「直播列表里点」才看得到。

**根因**：进入播放器有**两条互不相干的链路**——

| 链路 | 触发 | 代码 | 是否取公告 |
|---|---|---|---|
| `startPlay(item)` | 在播放列表里点卡片 | `MediaScreen` 1390-1414 行 | ✅ 取（含 `getOpenLiveOne` 兜底） |
| `playLiveId` effect | 首页直播卡 / 房间页 `navigate('Media', {playLiveId})` | `MediaScreen` 928-1003 行 | ❌ **从不取** |

`playLiveId` 链路里 `getLiveOne` 只被用来 `pickPlayableUrls` 解析播放地址，**没有读 `content.announcement`**。`HomeScreen.tsx:580` 的 `openLive` 走的正是这条路。

**修法**：在 `playLiveId` 解析链路里补一次公告设置（与 `startPlay` 同判定 + `getOpenLiveOne` 兜底）。**本清单编写时已改**（`MediaScreen` 约 970-990 行）。

**涉及文件**：`src/screens/MediaScreen.tsx`

**两个版本都要**

### B1. 直播弹幕列表文本截断（用户第一条反馈）

**现象**：弹幕列表（`DanmakuListSheet`）里的弹幕文字「被截断」。

**根因**：`numberOfLines={2}` + 固定行高 `ROW_H = 44`。两行文本 = `lineHeight 18 × 2 = 36`，
加 `paddingVertical 4×2 = 8` = **44，刚好顶满、零余量**。只要系统字体缩放 > 1.0 或字体度量
略有差异，两行就溢出 44，而 `getItemLayout` 仍按 44 步进 → 视觉上「文字被切掉」。

**定案（用户选择）**：**单行 + 省略号**，行高 `44 → 40`，`minHeight` 改**固定 `height`**
（`getItemLayout` 要求实际行高严格等于预测值）。已改。

**需求**：把电脑版的「在线人数」加到移动端。

**评估结论：移动端拿不到这个数据，已放弃。**

```
POST https://pocketapi.48.cn/live/api/v1/live/getLiveList   → 200

            liveMode, pictureOrientation, isCollection, inMicrophoneConnection,
```

状态机，明显是自采），移动端按官方 App 的接口拿不到。

## C. 已定位、已修（上轮审查结论）

### C1. `onMicStore` 扫描轮次竞态（P0）

**现象**：上麦页偶发「两位 worker 同时探测」→ 请求翻倍、进度条 `done` 双计数跳变。

**根因**：`scanStartedAt` / `scanAborted` 是**模块级全局量**，新一轮启动时无条件重置（`scanAborted = false`），于是被看门狗中止的**旧轮 worker 会被复活**，与新轮抢 `cursor`。

**状态**：**本轮已修**（改为每轮独立 `ScanRound` 令牌，worker 闭包捕获自己那轮；进度/结果写入前校验 `isCurrent()`）。

## E. 设置页描边问题（已修）

**现象**：设置页各个「框」的描边没描好。

**定案（用户确认）**：指的是**外圈分组卡**（关于/账号/外观/语言/…那些整块圆角卡）。

**根因**：**双层描边**。`GlassSurface` 内部本来就画一道描边（`MATERIAL.stroke`），
而调用方又在 `style` 里叠了一道 `borderColor: palette.hairline` + `borderWidth: hairline`
→ 两条线错位、圆角处不重合、深浅色主题下颜色互搏。

**修法（根因修，不是逐处贴）**：在 `GlassSurface` 里**接管**调用方传的
`borderWidth` / `borderColor`，交给内部那一层描边渲染，外层盒子剥离这两个属性。
调用方写法完全不用改、观感自动统一。全站 10+ 处同款写法（`LoginScreen` ×7、
`DownloadScreen`、`MemberDynamicScreen`…）一并受益。

同步把 `SettingsScreen` 的 `Section` 与 `styles.section` 里的重复描边删掉。
