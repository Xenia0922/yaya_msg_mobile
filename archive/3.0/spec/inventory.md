## 二、重点页详细方案

### 1. FollowedRoomsScreen（房间消息，4202 行，最重）

**现在（自上而下 6 层）**：房间切换 → 搜索 → 工具条 → 成员命中 → 公告 → 消息流；底部：输入条 + 小窗 + 底栏。

**问题**
- 顶部占屏 ~28%，消息只剩 2/3；
- 消息行内元素 6 个（头像/名字/队标/皇冠/时间/内容/回复卡），没有主次；
- 输入条与小窗、底栏三层叠加，键盘弹起时互相挤。

**v3 结构**
```
AppBar: 房间名 · 人数        [搜索] [更多]
Toolbar: 房间切换（横向文字）  |  只看成员  [直播中]
──────────────────────────────────────
消息流（唯一滚动）
  头像 36 | 名字(15) + 队标(12) + 时间(12, 右)
          内容(15, 最多 6 行)
          回复卡（左竖线 + 2 行，不用圆角块）
──────────────────────────────────────
输入条（贴底栏之上，键盘避让统一走 KeyboardAvoiding）
```
- 消息行**不再每条一个圆角卡**；同一个人连续发言合并为一段（头像只画一次）；
- 队标从"名字后的小图"改为**文字**（`Team HII`），只有房主/成员才显示；
- 时间右对齐 12px 元信息，不抢行；
- 公告折成一行可点开的提示条（默认收起）。

### 2. MediaScreen（媒体，2453 行）

**问题**：分类 + 筛选 + 播放器 + 列表同屏；播放器高度一变，列表起点就跳。

**v3**：列表页只做列表（AppBar + 一行分类 + 列表），**播放进独立页**（已有统一播放器）。
好处：列表不再被播放器挤动，滚动位置也不会因为播放/暂停丢。

### 3. PrivateMessagesScreen（私信，1175 行）

**现在**：会话行 = 头像 + 名字 + 预览 + 时间 + 未读，3 行高。
**v3**：2 行（名字 + 时间 12px 右对齐 / 预览 + 未读点），行高 64；未读用 6px 圆点而不是数字胶囊。

### 4. HomeScreen（首页，1080 行）

**现在**：工具 chips 11 个铺 4 行 + 快捷入口 2 行，首页像"功能目录墙"。
**v3**：
```
AppBar: 首页
搜索/问候（可选一行）
────────────────
主区：2 个大卡（房间 / 媒体）   ← 一屏唯一的大色块
────────────────
工具：横向滚动单行（翻牌/上麦/鸡腿榜/相册/统计/下载…）
────────────────
```
- 一屏只给两个主入口，其余收进横向工具行；
- 背景图保留，但**内容区不再叠玻璃**（背景都被卡挡住了，等于白做）。

### 5. SettingsScreen（设置，515 行）

**现在**：每项一张卡（圆角 + 描边 + 玻璃），一屏 5 卡。
**v3**：系统设置写法 —— `SectionHeader("播放")` + 行（label 左 / 开关右）+ `Divider`。
行高 52，开关右对齐；不再有任何卡片。

## 三、动画规范（v3 统一，页面不再各写一套）

| 场景 | 时长 | 曲线 | 说明 |
|---|---|---|---|
| 状态切换（颜色/透明度） | `DURATION.fast(140)` | linear | 开关、选中态文字 |
| 位移/展开（指示器、折叠） | `DURATION.base(220)` | 原生 spring（tension 240 / friction 26，与底栏一致） | 只动 transform，不动 width |
| 页面进场 | `DURATION.slow(320)` | ease-out | **只给首屏**，滚动加载不重复播 |
| 列表项进场 | 无 | — | 列表一律不做逐项动画（50 项逐个入场既卡又出布局问题，已踩过） |

**三条硬约束**
1. 同一元素上**不允许同时**有 blur + 描边 + 阴影（旧版三者叠加 = 脏）；
2. 跟手位移的值必须全程 JS 驱动（`useNativeDriver: false`），否则 native 迁移后 `setValue` 被静默丢弃；
3. 必须尊重系统「减弱动效」：`AccessibilityInfo.isReduceMotionEnabled` 为真时，只保留颜色反馈。
